## Performance formula v1.0

Delivery = min(accepted eligible weight / agreed eligible weight, 1) × 40.

Quality = task-weighted reviewed rating / 5 × 30.

Reliability = on-time accepted weight / accepted eligible weight × 20.

Teamwork = evidence-backed rating / 5 × 10.

Weights are 1/3/5. Dates attribute tasks by agreed due date in the configured period; original deadlines and scope history are retained. Approved leave requires an explicitly reviewed workload adjustment. Missing denominators or ratings produce Insufficient Evidence, never a complete partial score. Overtime, commits, and lines of code do not award formula points.

Known local database example: accepted/agreed = 3/3, quality 5, on-time 3/3, teamwork 4 → 40 + 30 + 20 + 8 = 98. Unit example: 34 + 25 + 15 + 8 = 82.

## Reliability boundaries

All multi-record commands execute within one PostgreSQL transaction; row/advisory locks and unique constraints prevent duplicate decisions and executions. Account invitation and document upload span provider services and use compensating/staged handling; they are not claimed to be cross-service atomic. Provider-level integration tests are still required.

## Task assignment, daily work quality, and worked time

- A project manager (or CEO) can assign a task to any active employee. The assignee is added to the project automatically, so no separate membership step is needed. The task records who assigned it, and My Work shows "Assigned by".
- A work log can carry the worker's own quality rating (0–5). It is shown to the reviewer only; the reviewed task rating still decides the quality score.
- Attendance is per account, so an employee can check in on one device and work on another. While checked in, each open browser sends a heartbeat every minute with a device id. Only the time between consecutive heartbeats of up to 3 minutes counts as worked time, so time while a computer sleeps or the app is closed is not counted. Check-out credits the final interval.
- A check-in left open for more than 16 hours without a heartbeat is closed automatically at the last time the employee was seen, so a forgotten check-out does not block the next day.
- CEO, HR, and reporting managers see each employee's name, check-in/out, worked time, away time, current presence (active/away), and devices. Worked time is app-activity time, not proof of productivity.

## Single session and remembered devices

- Each account has one active session. Signing in on another device replaces the previous session; the old device is signed out on its next request and shown a message. Database access for the replaced session stops immediately (`active_user()` checks the current session).
- Privileged accounts verify an authenticator code once per sign-in. If "Remember this device for 30 days" is ticked after a real code check, an HttpOnly cookie marks that browser; only its SHA-256 hash is stored. Sign-ins from that browser skip the code until the 30 days end or a password change, which revokes every remembered device. Database checks accept the remembered session through `mfa_satisfied()`; they do not accept an unverified session from an unknown device.
- Migration `202610130012` must be applied together with the app update. Sessions that existed before it are not tracked until their next sign-in.

## Multi-person tasks, overdue tasks, closing and deleting

- A task can be given to several people. Each person gets their own copy (linked by a shared group), with an optional description of their individual part. Each copy has its own status, evidence, review and quality rating, so every person's work is reviewed and scored separately. The task detail shows who else shares the task and their status.
- A task whose due date has passed and is not completed or cancelled is shown as Overdue (days late) on cards, in the detail view, and in an Overdue tasks panel at the top of My Work and Tasks.
- A project manager or CEO can close an unfinished task (cancel with a reason) or delete it. Deleting hides the task from every list but keeps it in the task history and audit trail. Completed tasks and tasks with submitted or approved work logs cannot be deleted; close those instead.
